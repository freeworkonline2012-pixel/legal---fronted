السبب:
بعد تجربة ربط بادج الثقة بمخرج حارس الهلوسة (hallucination-guard) كإشارة مركّبة،
كشف تقييم إجابة حية فعلية (تقدير 7/10 مقابل مستند مرجعي) عن خلل توليف حقيقي:
المادتان 159 و161 كانتا مسترجعتين بنجاح (ITB) لكنهما سقطتا من نص الإجابة النهائي
رغم توليد سليم غير مرفوض من حارس الهلوسة — أي أن الإشارة المركّبة نفسها لم تكن
لتكتشف هذا العيب أبداً. قرار المستخدم: إلغاء بادج الثقة بالكامل من الواجهة
والباك-إند معاً، بدلاً من الاستمرار في تكرار محاولات إصلاحه.

التحقق المنفَّذ فى بيئة العمل السحابية قبل الشحن:
- npm run typecheck (tsc --noEmit): نظيف، بدون أخطاء.
- npm test (jest): فشل أولى بفشلين فقط (اختباران كانا يتحققان من نص البادج
  القديم)، بعد الإصلاح: 233/233 اختباراً ناجحاً عبر 44 ملف اختبار.
- npm run build (next build / Turbopack): فشل، لكن السبب فحسب هو تعذّر
  الوصول لخطوط Google Fonts (IBM Plex Sans Arabic / Noto Naskh Arabic) بسبب
  عدم توفر شبكة خارجية فى بيئة العمل السحابية المعزولة — وهذا قيد بيئي وليس
  عيباً فى الكود. يُنصح بتشغيل npm run build على جهازك بعد السحب للتأكد
  النهائي أن البناء يمر بنجاح فى بيئة لديها اتصال فعلي بـ fonts.googleapis.com.
